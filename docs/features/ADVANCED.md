# Optional operations, modern/legacy formats, remote access and MCP (D-OPS-01 through D-OPS-05)

## Conversion and editing

Raw export streams logical disk bytes from qualified UDIF, no file-system interpretation needed. Raw import requires explicit length, geometry and chosen format; can wrap unknown filesystem data, but high-level filesystem creation HFS+/HFSX/APFS only. Container conversion preserves decoded virtual disk bytes when same geometry, rebuilds only container (including checksums), and reports changed signature/notarization state. Filesystem-changing conversion uses manifest read + metadata mapping, requires supported write backend and loss report; no claim that arbitrary partitioned/hybrid/unknown image can losslessly edit. `convert`, `edit`, `optimize`, `analyze` own bounded operations. `edit` uses immutable original + typed overlay operations add/remove/rename/replace metadata/layout; stable handles, preconditions original image digest/view, undo/redo and validation. Apply via rebuild into new image, require explicit overwrite if same target, preserve unknown records only when safe. No arbitrary raw binary patching as public editing API. Rebuild signed image invalidates trust; must explicitly re-sign. Resource free space and capacity recalculated; opaque unsupported metadata blocks lossless edit. Optimize and build-cache defined in PERFORMANCE.md. `analyze` measures compression ratios, allocation, largest content and run stats; optional build report provides stage times; no historical timing from image bytes.

`dmgez-operations` provides project-backed rebuild planning with its `edit` feature. It checks the exact source TOML revision, applies one atomic edit batch, and passes the validated project to the ordinary builder for unsigned, no-clobber publication to a fresh path. The original manifest and image remain available. This library path was exercised with a renamed file and exact payload readback from a new HFS+ image on macOS. [Rebuild planner](../../crates/services/dmgez-operations/src/edit.rs) · [Planner tests](../../crates/services/dmgez-operations/tests/project_rebuild.rs)

### Edit and rebuild a project

Compose the CLI with the HFS+ builder and `project-edit`. Pass the original project, a versioned edit batch and a fresh output path.

```sh
python3 tools/compose_filesystem_cli.py --hfsplus ../hfsplus --features project-edit
target/hfsplus-cli/debug/dmgez edit dmg.toml --changes edits.toml --output updated.dmg --dry-run --json
```

```toml
schema_version = 1

[[edits]]
operation = "modify"
target = "/My App.app"
destination = "/Updated App.app"
```

The batch runs in order. Use `add_copy` with `source` and optional `destination`, `add_directory` with `destination`, `add_symlink` with `destination` and `target`, `remove` with `target`, or `set_image_name` with `name`. A `modify` entry takes `target` and can change `destination`, `position`, `hidden` and `hide_extension`. Set `clear_position`, `clear_hidden` or `clear_hide_extension` to `true` to clear that field and omit its replacement. An empty `edits = []` requests a rebuild without overlay changes.

Project rebuilds with `finder-write` apply display overrides after capturing the host metadata. Clearing a project override restores the captured value. Use `hidden = false` or `hide_extension = false` to clear a specific bit in the rebuilt image. [Display overrides](BUILDER.md#build-stages-and-manifest)

Project source paths and `--output` resolve relative to the project directory and accept project substitutions from `--define NAME=VALUE`. The dry run resolves and validates the project and reports its SHA-256. Supply that value to `--expect-project-sha256` to require the same project revision on a later run. To build, omit `--dry-run`. The CLI verifies the staged UDIF, rechecks both TOML inputs, and publishes only to a fresh path. The original TOML and image remain intact. The new image is unsigned, and the report identifies any configured signing or notarization stages deferred by the rebuild.

The CLI regression tests cover the project-backed portion of D-OPS-01-T01 and D-OPS-01-T02. They exercise stale revision and occupied destination rejection, signed original preservation on macOS, unsigned output, and file data and resource fork read-back through the composed HFS+ reader. [CLI regressions](../../apps/dmgez-cli/tests/project_edit_cli/rebuild.rs) · [Test catalog](../reference/test-catalog.json)

### Edit an existing HFS+ image

The `dmgez-operations` library's `image-edit` feature admits a regular UDRO or UDZO file containing one whole-image HFS+ volume. It checks the container layout and declared CRCs, rejects opaque container resources, and records the SHA-256 of the complete file. For signed input it also checks the CodeDirectory digests. That observation establishes integrity against the embedded digest and carries no authenticity or notarization decision. Callers can revalidate the held file against its recorded revision and recheck its named entry before publication. [Source admission](../../crates/services/dmgez-operations/src/edit/image_source.rs) · [Admission tests](../../crates/services/dmgez-operations/tests/image_edit_source.rs)

```sh
python3 tools/compose_filesystem_cli.py --hfsplus ../hfsplus --features image-edit
target/hfsplus-cli/debug/dmgez edit-image original.dmg --changes edits.toml --output updated.dmg --dry-run --json
```

`edit-image` accepts the version-one edit batch above. It can rename or move entries, remove entries and directory subtrees, copy local files or trees, create directories and symlinks, set the volume name, and edit Finder positions and display flags. Targets resolve against the original catalog under HFS+ name matching. A move supplies the final absolute image path. New destinations need an existing or explicitly added parent directory. [Overlay implementation](../../crates/services/dmgez-hfsplus/src/rebuild/overlay.rs)

`add_copy` resolves a literal host path relative to the edit batch directory and uses the source basename at the image root when `destination` is omitted. A directory copy walks its descendants without following symlinks. Supported host hard links, modes, forks, Finder information, and inline attributes use the same capture rules as a project build. To replace an existing entry, remove it in the same batch and add the copy at that path. A destination inside a copied host directory is refused before staging. The image editor reserves `.DS_Store` paths for its own layout handling. [Host copy preparation](../../crates/services/dmgez-hfsplus/src/rebuild/prepared.rs)

The default `--metadata-policy strict` refuses host inputs when the writer cannot retain their requested metadata. Use `--metadata-policy report` to permit and report host metadata losses such as timestamps below HFS+ granularity or attributes the host adapter cannot observe. The policy applies only to added host content. Source admission and preservation requirements for the original image are always strict.

The rebuild preserves exact retained data and resource forks, supported inline attributes, regular-file hard-link groups, modes, owners, timestamps and admitted Finder information. It refuses profiles with a journal, overflow records, fork-backed attributes or unsupported private catalog metadata. The rebuilt volume regenerates its catalog and allocation structures, keeping at least the source capacity and growing as needed. [HFS+ rebuild](../../crates/services/dmgez-hfsplus/src/rebuild.rs)

Use `hidden` and `hide_extension` to set or clear the corresponding FinderInfo bits on a file, directory or symlink. `clear_hidden` and `clear_hide_extension` clear the respective bits, and omitted fields preserve them. This leaves the name and every other FinderInfo bit intact. A symlink edit affects the link itself. A hard-link edit affects the shared inode and all surviving aliases. When multiple edits set the same bit, the last one takes effect. The editor refuses changes to application bundle paths, recognized signed bundle contents and files with signing indicators. [Finder flag regressions](../../apps/dmgez-cli/tests/image_edit_cli/finder_flags.rs) · [Apple code-signing restrictions](https://developer.apple.com/library/archive/qa/qa1940/_index.html)

Qualified single-leaf `.DS_Store` files retain their window and view settings, including the store that dmgez generates by default. Positions follow renamed or moved items and disappear when their items are removed. Set `position = [x, y]` for nonnegative whole points, or set `clear_position = true` to remove a position. Positioned names use the store writer's printable ASCII profile. When a destination folder needs a store, the editor creates one with default settings. Unaffected stores retain their exact bytes. Opaque records and unqualified store encodings cause a refusal before publication. [Finder store editing](../../crates/presentation/dmgez-finder/src/edit/catalog.rs)

The editor preserves canonical image background aliases that identify an ordinary file in the original catalog. It checks the stored path, volume and target creation dates, and target and parent catalog IDs against the held image. If the volume label, target path, or catalog IDs change, it updates each surviving store to point to the original file at its new location. A surviving store blocks removal of its target, including replacement under the same name. [Background alias regressions](../../apps/dmgez-cli/tests/image_edit_cli/background.rs)

Use `--expect-image-sha256` with the hash from a dry run to pin the image revision across commands. Host inputs are captured anew for each invocation. Omit `--dry-run` to publish a fresh unsigned image. Before publication the CLI reopens the stage, checks the container and decoded byte digest, checks the HFS+ structure, and revalidates the original image, edit batch and captured host inputs. A signed original stays intact and the rebuilt image needs its own signature. [CLI verification](../../apps/dmgez-cli/src/image_edit/execute.rs)

The existing-image regressions cover D-OPS-01-T01 for the admitted overlay operations and D-OPS-01-T02 for signed no-op rebuilds and opaque layout refusal. On macOS, the fixtures compare icon positions, retained folder settings and both forks, check that the signed original is byte-for-byte intact, and run `hdiutil verify` on the rebuilt image. Host copy tests also cover strict refusal and reported metadata loss, exact copied forks, and replacement of a prepared host path. [Host copy regressions](../../apps/dmgez-cli/tests/image_edit_cli/host_copy.rs) · [Finder regressions](../../apps/dmgez-cli/tests/image_edit_cli/finder.rs) · [Signed rebuild regressions](../../apps/dmgez-cli/tests/image_edit_cli/rebuild.rs) · [Test catalog](../reference/test-catalog.json)

### Analyze HFS+ allocation and file sizes

Compose with `hfsplus-analysis` and pass `--hfsplus` to add a filesystem section to the container analysis.

```sh
python3 tools/compose_filesystem_cli.py --hfsplus ../hfsplus --no-default-features --features hfsplus-analysis
target/hfsplus-cli/debug/dmgez analyze installer.dmg --hfsplus --largest 20 --json
```

The HFS+ and HFSX report checks free blocks and special-file allocation against the bitmap and distinguishes the remaining allocated blocks from verified ownership. The file ranking uses logical data-fork lengths and includes stored paths and inode IDs. Hard-link paths can share an inode. The report flags a walk cut short by the entry or depth ceiling and counts any unavailable sizes. Use `--partition` to select a specific window on a partitioned image. [Analysis regressions](../../apps/dmgez-cli/tests/volume_cli/analysis.rs)

## Modern variants and stretch matrix

`ulfo`/LZFSE and `ulmo`/LZMA (not assumed XZ) qualified by actual macOS output and decoder checks; separate codec gates. `udrw` project output emits the trailerless HFS+ bytes used by Apple’s modern raw-backed profile. Select `--raw` when reading that image. [UDRW profile](UDIF.md#raw-backed-udrw-project-output) The optional project writer supports a single HFS+ or HFSX volume on a new GPT or APM disk. [Partitioned project output](BUILDER.md#write-an-apm-or-gpt-disk-layout) Multiple partitions/volumes explicit selection. Sparse image, sparsebundle and ASIF are distinct optional formats: classify, map holes/bands and verify bounds; sparsebundle is directory container with manifest/band ownership, reject traversal/symlinks, atomic manifest updates and crash safety before writes/compaction. ASIF is research-gated, never infer rules from filename; need evidence for macOS-specific variant. Segmented images (`segmented`) require segment identity/count/number/running offsets, bounded segment resolver and no remote/path discovery outside authorized root. Legacy off by default umbrella: UDBZ/bzip2, UDCO/ADC, old UDIF variants, NDIF, DC42 read first then qualified write; exact variant ledger, separate parser for non-UDIF families; no modern OS mounting claims for obsolete formats. Classic HFS filesystem support is a separate independent effort only if needed, not an implicit requirement of reading legacy containers. Deprecated license resources `license` off by default: locale/default-language mapping, plain text/RTF, label/buttons mapping, resource serialization qualified against old and current tools; unsupported native presentation explicitly documented. No arbitrary RTF execution. These gates are stretch/nonblocking even if historically supported by dmgbuild. Encryption: detect supported envelopes and differentiate from APFS volume encryption. Research algorithms/framing/key records with lawful fixtures; use established crypto, explicit credentials, bounded KDF iterations/key records/ciphertext sizes, no brute force or recovery/bypass. Read-only first, create/rotate only after independent Apple interoperability, tamper/error tests and security review. Some encryption modes may not authenticate all ciphertext; do not call them authenticated or secure by default. Keep keys and plaintext caches ephemeral and scoped, zeroize where feasible. Never claim password changes securely erase old copies. No writable mounts or unsafe in-place edits until filesystem crash consistency plus container persistence proven.

## Remote reader

`remote` HTTP(S) ReadAt optional. Explicit URL user intent, no auto downloads, TLS verify, bounded redirects and ranges/time/bytes. Fetch HEAD or bounded range to determine size and strong ETag/immutable version; use `Range`, `If-Match`/`If-Range` as appropriate and require correct status/Content-Range/length. Reject mismatched responses and changing identities, no silently mixing versions. If server lacks stable validators/range support, fail or explicitly offer bounded local download, not unbounded fallback. No decompression of HTTP transfer that invalidates offsets (request identity encoding). Cache key includes URL + strong identity and run; private cache permissions, no secrets/auth headers in logs. MCP remote feature must explicitly allow configured domains and deny private/link-local/metadata IPs, DNS rebinding and redirects across trust boundaries; local CLI user explicitly choosing local endpoint is distinct policy. Signed URLs redact query. No network access in default builder or reader. Test mock range server returns 200, 206 malformed/short, 416, changed ETag, redirect to disallowed target, timeouts, truncated image and cancellation; measure metadata-only transfer. No claim inspect arbitrary URL without validating server behavior.

Build the CLI with `remote` to inspect an explicitly supplied HTTP or HTTPS URL.

```sh
cargo run --locked --no-default-features --features remote -- \
  inspect --url 'https://example.com/installer.dmg' --json
```

The endpoint must return single-range `206` responses with exact `Content-Range` and `Content-Length` headers and a strong ETag. The first request reads one byte. Later requests send `If-Match`, and the CLI checks the revision again before emitting a report. The HTTP client verifies HTTPS certificates, refuses redirects and encoded responses, and disables proxy discovery. The URL and query stay out of dmgez reports and errors. [HTTP conditional requests](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)

The session allows up to 512 requests, 64 MiB of reserved response body bytes, and 30 seconds total, with a 16 MiB per-range ceiling. Standard inspection reads the container metadata. Add `--partitions` to request a bounded decoded disk probe. The CLI remote profile has no disk cache or whole-image download fallback. D-OPS-03 loopback tests cover bounded metadata transfer, malformed responses, redirects, timeouts, and refusal to emit a report after a revision change. MCP remote access remains a separate admission profile. [Range transport tests](../../crates/services/dmgez-inspector/src/remote/http/tests.rs) · [CLI tests](../../apps/dmgez-cli/tests/remote_inspect_cli.rs)

## MCP

Separate `apps/dmgez-mcp` using rmcp, local stdio by default. No unsolicited outbound network or listener. Tool schema version and capabilities; list/read project, create validated project, add content, update layout, preview PNG with bounds, plan/build, inspect/list/stat, diff, verify, lint, propose edit; release/install/mount/extract/overwrite/remote require explicit user authorization and appropriate compiled services. Tool inputs typed, size-limited and validated; structured responses include statuses, diagnostics, stable IDs, pagination and safe paths. Never expose arbitrary command execution, shell strings, unrestricted `--set` or credentials. Restrict input/output to user-configured roots using handle-based confinement and deny symlink escape; approvals bound to operation intent, canonical paths, digest, revision and expiry, single-use; MCP client permissions alone are not blanket consent. Server must not interpret image text/README as commands; return untrusted data. No automatic execution of image contents. `preview` renders via shared headless service, only allowed image dimensions. `project_update` applies typed changeset with expected revision, validation and dry-run diff; commit only with explicit approved mutation. `build` uses immutable plan, returns artifact path only within approved root. Expose job IDs for long-running requests only within running session; cancellation and limits. Audit metadata without secrets (tool, time, path scope, outcome, approval ID). No unrelated UI automation as prerequisite; optional GUI integration uses same services and explicit session connection. JSON schemas derive from domain request types; protocol handshake tests, invalid args, path traversal, malicious instructions, unauthorized side effects, concurrent revision conflict, cancellation, large report limits, capability disabled. MCP not linked into CLI.
