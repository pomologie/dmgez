# Inspector, virtual filesystem, verification and extraction (D-READ-01 through D-READ-05)

## Open and detect

Reader constructs `ImageSession` over immutable bounded source, supports unsigned/signed standard UDIF and eventually recognized other envelopes; no mount required. Detection recognizes raw when explicit or strong filesystem/partition evidence. No arbitrary `.dmg` extension trust. Enumerate UDIF tables separately from actual disk partitions; a blkx name is not proof of GPT/APM. Detect unpartitioned volume via filesystem header with validated bounds; parse protective MBR/GPT primary and backup headers/entry CRC and bounds, extended MBR chains with cycle checks, APM map count/block size/partition range with selected focused libraries. Ambiguity/hybrid/overlap gets diagnostic, explicit selection; not a silent first match. Partition offsets are logical disk bytes; report all units. Unsupported filesystem yields metadata/raw partition export, not fake file tree. APFS container can present several volumes, select by UUID/object identity and optional XID. No FAT32 interpretation requirement. Read-only `VolumeView` follows C5, source identity immutable. `dmgez-vfs` adapts independent engines; does not implement their formats.

## Reports and commands

`inspect image` compact overview: container format/profile, physical size, virtual disk size, sector unit, codec(s), segment count, declared checksums status (not checked by inspect), encryption/signature flags, partition and supported volume summaries. `--all` includes bounded detail; full unbounded listing requires explicit pagination/export. `--container`, `--blocks`, `--partitions`, `--filesystem`, `--tree`, `--path`, `--finder`, `--raw-records`, `--volume`, `--offset`, `--limit`, `--depth`, `--json`. Reports support stable schema versions, typed offsets and ranges; physical compressed runs cannot necessarily map exact compressed byte subrange to file byte, label covering runs only. No reading large content by default. `ls`, `tree`, `stat`, `cat`, `extract`, `verify` use same services, not reparse via separate ad hoc commands. `cat` outputs exactly file data, `--fork resource` explicitly selects fork. Directories error for cat; link metadata distinct from dereference. Never print secrets or unbounded raw xattr data unless requested and capped. Escape hostile terminal controls; JSON output machine-safe. Report actual raw unknown bytes as hex/base64 only within budget.

Inspector depths: (1) UDIF trailer, version, resource plist keys, block-map table/run type, raw/encoded offsets and sizes, checksum descriptors, partition context, signing metadata; (2) virtual disk geometry, MBR/GPT/APM names/UUIDs/types/start/end/flags/CRC, nonallocated regions; (3) volume header/flags/version/journal state/UUID/name/allocation blocks/counts/creation & modification dates, special files, B-tree header/node map, catalog counts/extents, allocation/free metrics, file forks and attr trees; (4) file node CNID/parent/type/link group/target/logical vs allocated size/permissions/uid/gid/timestamps/Finder flags/type+creator/xattrs/resource forks/physical extents and covering UDIF runs; (5) Finder raw records, decoded view/layout/background alias/icon reps; (6) detailed parser diagnostics and unknown fields. Internals like journal or HFS private directory visible only explicit internal inspection, not ordinary extraction. Deleted-file recovery and carving excluded.

## Browse HFS+ and HFSX

The composed CLI's `hfsplus-read` feature adds `ls`, `tree`, `stat`, and `cat` over the shared volume view. Inputs default to UDIF. Use `--raw` to interpret an input as a raw disk image. When the partition map has more than one eligible data window, pass the desired one-based `--partition` slot. For UDIF images, `inspect --partitions` shows these slots. The commands open the image read-only and use bounded filesystem reads within the selected extent.

Use absolute paths within the selected volume. The filesystem matches names using the selected catalog's comparison mode. Listings preserve catalog order, and JSON reports preserve stored UTF-16 units. `ls` accepts an offset and page limit. `tree` accepts depth and entry limits. `stat` reports the catalog node ID, POSIX metadata, and link information. Symbolic links appear as link objects, and their targets are never traversed. `cat` emits exact logical data or the explicitly selected stored resource fork on stdout. A read or output failure exits nonzero and can leave a prefix in the sink. The standard composition keeps compressed HFS+ logical file decoding disabled.

The D-READ-03 compatibility checks used an instrumented 16 GiB logical disk containing native HFS+ metadata. Layout discovery, the first directory page, and hard-link metadata used 55 reads totaling 195,118 bytes and avoided user payload blocks. Targeted data and resource reads each fetched exactly seven bytes at independently recorded physical offsets. ## Verify is separate

`verify --quick` validates headers, ranges, map coverage, supported checksums declared as not checked if not computed; `verify --container` streams required CRC domains; `verify --full` also checks supported filesystem invariants, file data access, attribute records, and optional requested source manifest. Distinguish structural, payload, filesystem and security statuses. No signature trust claim from checksums, no Gatekeeper inference. Missing codec => unsupported with nonzero exit if requested verification needs it. Corrupted volume cannot be silently repaired. Verification reads bounded chunks, never extracts or launches. Report errors capped with count of suppressed errors and traversal budgets. Native `fsck_hfs -n` and `fsck_apfs -n` in disposable test devices only after tool syntax checked on runner. Source remains read-only. `inspect` can return partial report and diagnostic; no implicit `passed` status.

The composed CLI's optional `hfsplus-verify` feature connects `verify --full` to the sibling HFS+ and HFSX reader. The inspector checks the container CRCs before admitting a single filesystem data window. The reader sees window-relative, budgeted reads and checks the reachable catalog, fork layouts, attributes, and allocation structures in its supported profile. Multiple candidate data partitions require separate selection support.

A completed structural check reports `filesystem_scope = reachable_structure` and a partial outcome. The command exits nonzero because checking all file payloads and global ownership remains open. Unsupported profiles, exhausted budgets, corrupt metadata, and read failures have separate report categories. Container verification and quick checks keep their existing scope.

With defaults disabled and only `hfsplus-verify` selected, package composition needs the reader, format, and core archives. The builder archive is required when composing project-build support.

The CLI tests cover the HFS+ filesystem in a native APM image, partitionless native HFS+ and HFSX, and a catalog count corruption wrapped with valid UDIF checksums. The corrupted case keeps container payload status passed and reports filesystem corruption. These checks cover the reachable filesystem portion of D-READ-04-T01. ## Extraction and installation primitives

Extract selected paths/trees or all to explicit destination; dry-run preflight path/name collisions on host (case-fold, Windows reserved names, trailing dots/spaces, alternate data streams, normalization, file/dir conflicts). Strict lossless mode refuses unsupported host names, attrs, symlinks or hard links; optional explicit reversible escaped-name/metadata-sidecar policy, with machine-readable report. Ensure output confinement using handle-relative, no-follow operations and verified directory identities; protect against image path traversal and existing destination symlinks/junctions/reparse points, absolute symlink traversal, `..`, link races, and TOCTOU. No extraction through symlinks or outside authorized root. Store symlink as link only when supported and explicitly permitted by target policy; external targets remain inert, warn or refuse by policy. Never follow links while writing. Preserve hard-link groups only within authorized extraction set; materialize copy and report if needed. Regular file staging before replacement, no-clobber default, explicit per-conflict policy `skip|rename|replace`, and atomic where supported; whole directory transaction best-effort with journal/report, not global atomicity. Permissions/ownership apply safely after data writes; no elevation, setuid/device nodes disabled by default; preserve requested executable bits but do not execute. Preserve resource fork/xattrs including metadata sidecar where needed; warn and strict-fail on losses. Quarantine/security provenance not removed; install workflows integrate with platform security. Never extract HFS private metadata as ordinary files. Cancel cleanup only owned staging. On unsupported encrypted/compressed content report exact error, never output misleading zero-length file. Test malicious paths, symlink races, huge virtual images and decompression bombs, unsupported metadata, duplicate names, partial failures, loss report, signed app extraction, data fork/resource fork independently.

## Caching and remote

Cache decoded runs by immutable image identity and run descriptor within byte budget; `ReadAt` splits requests and single-flight decodes on miss. Cache metadata separately. Sequential reads can read-ahead within bounded credits; random reads do not decode unrelated runs. Remote optional adapter in ADVANCED.md. Reader tests instrument I/O to assert metadata-only inspect does not read whole payload and one file fetch reads only needed catalog/data runs. A full checksum may need entire image; explicit command. No active device or privileged filesystem access needed.
