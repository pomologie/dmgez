# Native UDIF format and I/O (D-UDIF-01 through D-UDIF-06)

## Profile, evidence and parser design

Reference IDs S01-S05 in the ecosystem reference register. UDIF is not assumed to have a complete official public specification. Build an independently written field ledger from native fixtures, public format research and permitted reference APIs. Treat observed rules as version/profile-qualified. Initial profile: ordinary single-file, single-segment, unencrypted UDIF, version 4 trailer, XML resource plist, 512-byte logical sector unit, UDRO and UDZO output. Input may contain multiple block-map tables; write a partitionless HFS+ payload first, then optional partitioned layouts. `format=raw` is raw logical disk export, not an XML/trailer variant. Keep container geometry independent from filesystem block geometry.

Implement `trailer`, `resource`, `blkx`, `checksum`, `index`, `codec`, `reader`, `writer`, `validation` modules inside `dmgez-udif`. Use an explicit bounded cursor, endian decode and checked integer arithmetic. Treat FourCC and unknown numeric tags as data. No transmute or memory-map reinterpretation of untrusted bytes. A `ContainerDescriptor` contains physical file length, logical size, ranges and raw metadata; `RunIndex` contains normalized disk intervals and physical data slices, with original raw record and provenance. Use lazy decode; parser must not inflate payload to obtain metadata.

### Trailer and resource inventory

`koly` is the fixed 512-byte trailer in the standard profile. Validate magic, version, header length, data fork/resource fork/XML ranges, segment numbering/ID, image variant, sector count, checksum descriptors, reserved/unknown bytes, and signature ranges when present. Check all offsets against actual file length and prevent ranges crossing trailer; qualify legitimate overlap/signature placement with fixtures. Do not hard-code a single resource ordering or treat signed tail data as compressed payload. Distinguish resource plist XML/binary availability by profile; emit deterministic XML for first writer. Parse bounded dictionaries/arrays, base64 blobs, named/numbered `blkx` resources, identifiers and associated keys. Retain unknown resource keys in read reports, and preserve only with an explicit supported rewrite policy. Refuse recursive XML expansion/external resolution; enforce length before allocation. Record resource fork vs XML variations as separate profiles; no guessing.

`mish` block tables: validate magic/version, first logical sector and length, data offset/base, buffer requirements, descriptors, checksum header, run count and record bounds. Normalize table-relative sector and data offsets only once. Raw runs, explicit zero and ignore run kinds, comment and terminator, zlib and optional codecs are distinct. Record original type, flags/comment, logical start/count, compressed offset/length. Known type codes and exact field sizes go in a fixture-backed binary ledger maintained with implementation; use reference APIs to cross-check rather than mechanically translate code. Structural parser can recognize disabled codecs. Unknown non-data control records may be reported but not guessed to be data. Comments/terminator do not cover sectors. Reject arithmetic overflow, ambiguous overlaps, unterminated/overlarge tables, illegal payload lengths or uncovered ranges in a strict complete disk view; only profile-evidenced intentional gaps map to zeros. Explicit zero vs ignore semantics must be separately qualified; do not coalesce them in checksum logic. Inspect may report a partial index for an unsupported table without permitting reads through it.

### Checksums and signing boundaries

Maintain independently computed coverage for physical data fork, logical table payload, master image checksum and any other descriptor. Use standard CRC32 primitive but qualify byte ordering, scope, excluded/zero/ignore regions, padding, initial/final values and master checksum composition per profile. Build a native fixture ledger containing each checksum input range and expected numeric value, including all-zero, mixed compressed/raw, leading and trailing gaps, multiple tables, and signed/stapled images. Do not infer master digest equals CRC of full logical disk. Unknown checksum algorithms are `unsupported`; absent checksums `not_present`, not `passed`. For `verify --container` compare checksums actually declared and supported, never fabricate trust. No cryptographic authenticity implied by CRC. Signed DMGs can contain additional signature data and offsets; reader exposes metadata, signing service owns changes to staged file, and final verification reopens signed/stapled output. Writer deliberately emits qualified unsigned layout; no signature placeholder guess. Signing and stapling may change trailer fields; tests compare source disk bytes and native verify before/after.

## Writer algorithm

1. Accept a finite aligned source with declared byte length, profile, volume/partition description, and output `Write` sink; allow callers to specify a checked virtual disk layout. A raw non-seekable input can be accepted only with known length and sequential reads. Reject unexpected trailing/short bytes. Check source/output identity in path service. Configure deterministic chunk size (default proposal 1 MiB, multiple of 512; qualify against native tool), codec level, maximum physical/logical sizes and budget before work. Single logical stream; no full raw filesystem file.
2. Enumerate runs in logical order. Detect all-zero chunks and merge adjacent compatible zero runs subject to format limits; choose canonical qualified zero type. UDRO writes raw data for ordinary regions and only uses zero encodings if native fixtures prove allowed. UDZO compresses each independent run as exact qualified zlib stream; optionally choose raw if compressed output is no smaller under deterministic rule. Maintain logical offsets, raw lengths, checksum inputs and file offset cursor using checked arithmetic.
3. Serial encoder is reference. Optional Rayon workers receive disjoint immutable byte buffers, independently encode and produce per-run data/checksum summaries. Bounded in-flight window; ordered consumer writes runs and records actual offsets, updates physical checksum. For logical checksum, hash raw chunks in producer order or use a proven CRC combine in order (never combine arbitrary CRCs). Avoid deadlocks from workers waiting for ordered consumer while holding all credits. Writer cannot pull another run until budget released; see performance spec.
4. Retain or spool bounded run metadata (not payload). Finalize `blkx` tables, resource plist, final 512-byte trailer and all qualified checksums; update cursor from exact bytes written. Sequential sink does not need backpatch for standard unsigned profile; confirm this with nonseekable sink tests. Commit only after all writes succeed and requested verification finishes. Failed stream explicitly invalid; path output staged and atomic where possible.
5. `WriteReport` records logical/physical bytes, raw/zero/compressed run counts, codec/profile, checksum status, stage times and peak owned buffers. Bytes emitted before error are not a valid artifact.

## Reader and verification algorithm

1. Open immutable `ReadAt` source; read tail only, bounds-check trailer and resource metadata, classify format. Encrypted/segmented/sparse envelopes go through explicit adapter only if enabled. Unknown unsupported magic yields diagnostics, no generic raw fallback unless explicitly requested or independently confirmed.
2. Build sorted logical run index for selected virtual disk, validate mapping. Binary-search by sector/range, split request across runs and bounded partitions. Read compressed ranges exactly, decompress into capped length known from sectors, require decoder EOF/consumption per qualified framing, reject overrun/short stream and unsupported codec; don't allocate attacker-provided full disk length. Raw exact read; defined zero/ignore according to qualified profile. Use bounded LRU byte cache keyed by image identity+run+decoder profile, avoid duplicate concurrent inflate; wipe decrypted cache when applicable. Random-read tests cross boundary, end-of-disk, zero/ignore, raw/zlib, mixed and huge sparse images. Provide a streaming decoded disk sink without mounting.
3. `inspect` reports metadata and optional run windows without decoding all runs. `verify` checks structure then streams required checksum domains, can independently verify filesystems; `--quick` structural only, `--full` includes actual decoded payload. Partial unsupported variants are not valid verified images. Corruption diagnostics include logical and physical locations. Never repair input in place.

## Optional modern and legacy formats

ULFO/LZFSE and ULMO/LZMA use separate features, with native framing and decompressed-length fixtures; do not confuse XZ or LZMA-alone wrappers. UDRW read and raw-backed write profile requires its own qualified rules; don't treat it as obsolete or automatically writable on disk. Multi-table, partitioned images, signed/stapled inputs and larger run limits expand independently. `legacy` off by default: ADC/UDCO, bzip2/UDBZ, obsolete UDIF, NDIF and DC42 are separately qualified; some are not UDIF and must not go through a fake `koly` path. Encrypted and sparse/ASIF inputs separate envelope/format adapters. See ADVANCED.md. Test corpus labels native tool, OS build, image profile, codec and exact supported checksum rules. References provide corroboration, not proof. No production calls to fstool, udif or apple-dmg.
