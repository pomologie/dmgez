# Mounting, installation and safe auto-ejection (D-MOUNT-01 through D-MOUNT-03)

A DMG itself is passive. It does not contain a supported automatic event handler for Finder copies, and dmgez must not inject autostart executables. The preferred GUI experience is a virtual, interactive volume over the VFS, with no OS mount, privileges or driver. `dmgez mount` is an explicit optional service for actual host paths. Both modes share read-only data and metadata interfaces; never expose virtual paths as real host paths. All mounts read-only until an independently qualified transactional filesystem writer and container-write contract exist.

## Backends and session lifecycle

`mount-system` macOS: use trusted absolute system executable/API and safe argv, capture structured plist output from supported attach tooling, attach read-only with explicit chosen mount point if supported. Detect `hdiutil`/`diskutil image` support rather than assuming exact flags on all OS versions. Never parse localized human output as authoritative device identity. Only detach a session's actual device/volume handle after checking identity; don't unmount arbitrary path. `mount-fuse`: Linux FUSE and optional macFUSE or FSKit integration where qualified; expose read-only filesystem from VFS with bounded inode mapping, stable node IDs, correct lookup/read/stat/readdir semantics and supported xattrs/forks; return proper platform errors for unsupported functions. `mount-winfsp`: Windows WinFsp, driver/runtime install externally, target-gated. Map case sensitivity, Windows name constraints and links explicitly; reject unsupported names or present documented reversible view without mutating content. Do not install kernel drivers automatically. macOS native mount gives best real Finder behavior; virtual driver compatibility need not match Finder mount options until tested. Backend errors and driver absent are `BackendUnavailable`.

`dmgez mount image [--mountpoint PATH] [--backend auto|system|fuse|winfsp] [--detach]`; `mount list|status ID|stop ID`; `unmount ID` or exact verified mountpoint. `auto` chooses available explicitly supported backend, not implicit privilege escalation. Use session state `Starting -> Mounted -> Watching? -> Verifying? -> UnmountRequested -> Unmounted`, with `Busy`, `Failed`, `Cancelled`, `Orphaned` alternatives; never mark unmounted until OS confirms. Store per-user session records (version, unique session ID, PID+start identity, canonical source identity, backend/device, mountpoint, owner, monitor intent, timestamps/status) in secured local runtime directory, not secrets. Foreground default, detached explicitly launches controlled helper/service with private IPC; supervisor manages process lifetime and graceful cancellation; stale PID reuse never signals unrelated process. Lock session edits, reconnect only matching owned session, no global daemon or persistence without user request. User `stop` stops watch and optionally asks safe unmount; define exact behavior in CLI spec. Do not force detach on busy volume or unverified device. On crash report/reconcile actual mounts; cleanup only owned temporary mountpoints, do not delete mounted paths. OS-native or FUSE driver privilege requirements surfaced before mount. Ensure cancellation and shutdown join outstanding VFS reads.

### macOS system mount sessions

Build the CLI with `mount-system` to attach a supported partitionless, single-volume HFS+ UDIF image read-only through `hdiutil`. dmgez verifies the held image before handing it to the system and disables `hdiutil`'s verification cache and automatic volume checks. Press Return to detach a foreground session. Use `--detach` to leave the OS-managed attachment in place and return its session ID. By default dmgez prepares a private mountpoint in the session directory. To choose the mountpoint, supply an existing empty directory.

```sh
dmgez mount installer.dmg --backend system --detach
dmgez mount list
dmgez mount status SESSION_ID --json
dmgez unmount SESSION_ID
```

`mount list` reports saved records. `mount status` checks the recorded attachment against the current system when an attachment identity is available. `unmount` and `mount stop` accept a session ID and recheck the named image, mountpoint, and device before a non-forced detach. Coordinate external mount tooling with dmgez because the system recheck and detach are separate operations. An ambiguous attachment or changed identity leaves a record for inspection. Foreground sessions also remain recorded if the CLI exits before completing detach. [CLI regressions](../../apps/dmgez-cli/tests/mount_cli.rs)

## Virtual install and external copy

`install image --app /App.app --destination /Applications` on macOS, explicit user action. On other hosts extract bundles to explicit directory only, no claim that macOS executables can run there. Stage copied bundle in destination parent, preserve metadata, verify bytes/symlinks/modes/forks/xattrs under selected strict policy; native signature/Gatekeeper checks only if compiled/available and requested. Respect quarantine and OS permission/authorization; never remove security flags, never use sudo implicitly. Validate target identity, avoid symlink traversal, no overwrite by default, explicit collision confirmation, existing app running warn/refuse replacement. For safe upgrade use staged directory, platform atomic swap where available, otherwise explicit rollback strategy and failure journal; do not claim transactional multi-app install. Verify completed output, then optional close GUI. Multiple bundles use explicitly selected entries; no blanket execution or install of hidden contents. GUI external drag promised-file semantics and staging fallback see GUI.md. Because dmgez owns copy, it can know successful completion without filesystem watchers; file promises only call completion after data verification and report error/cancel. Preview remains usable on nonmountable platforms.

Compose the CLI with `hfsplus-install` or `apfs-install` on macOS or Linux. Run `dmgez install IMAGE --app /App.app --destination DIRECTORY`. Use `--filesystem apfs` to select APFS and the standard reader options to select the raw input, partition or APFS view. `--dry-run` checks bundle layout, source inventory, host profile and destination availability. `--max-bytes` lowers the total payload budget. `--json` reports the selected application, destination, planned payload, publication status and any retained staging name.

Installation checks the selected `.app` layout, including the exact executable declared by its bounded XML or binary `Info.plist`. The copy plan resolves every entry within the retained view and inventories payload sizes and metadata before any writes. The executor copies into a private directory beneath the explicitly authorized destination. It compares regular data against the source through a separately opened descriptor, verifies modes and attributes, and checks link payloads in place. One no-clobber rename makes the verified bundle visible. On failure a nonempty private stage may remain under its reported name. Supply a stable local destination where inherited ACLs and other writers cannot modify the private staging tree. [Copy plan and execution](../../crates/services/dmgez-operations/src/install.rs)

The admitted profile reproduces regular files, directories and confined relative symlinks. On macOS it also reproduces supported extended attributes, effective FinderInfo and resource forks. Linux supports `user.*` attributes and its native symlink permissions. Ownership comes from host creation. Timestamps, ACLs, flags, hard-link groups, compressed records that require their storage attributes, and metadata outside these profiles have separate fidelity requirements. Quarantine that the copy cannot preserve stops the operation. Existing destinations are preserved, including dangling links. Upgrades, Windows export, and native drag-out have separate qualification work.

With `signing-native` on macOS, pass `--verify-app-signature` to require Developer ID application verification on the private staged copy. Pass `--assess` to require a separate Gatekeeper assessment. Each requested check must pass before publication. The copy then rechecks staged contents and the held source before the final rename. A dry run records checks as pending. ## Monitor external Finder copies

The macOS install service can compare an existing bundle with the admitted copy plan and held source. It checks exact entries, file bytes, symlink targets, and the admitted metadata through held destination descriptors. A final namespace and change-stamp check establishes the observed match. The watcher requires separate freshness evidence. [Existing bundle verification](../../crates/services/dmgez-operations/src/install/execute/native/existing.rs)

### Foreground watch of a recorded macOS session

Compose the CLI with `--features mount-watch`. Create a recorded read-only session and start the watch before copying the application.

```sh
dmgez mount App.dmg --detach --json
dmgez mount watch SESSION_ID --watch-install /App.app \
  --destination /Applications/App.app --auto-eject --timeout 300
```

Pair repeated `--watch-install` and `--destination` options in order. The watcher expects every pair unless you pass `--match-any`. Each destination must end in the exact application basename under an existing, explicitly selected local directory. The watcher checks for a new directory identity relative to the initial observation, then waits for a quiet interval and compares the exact copy. A directory already present at the start must be replaced by a different object to count. An in-place update to the original directory does not authorize detachment.

The watcher keeps the original image handle and checks the session revision before requesting ordinary non-forced detach. It rechecks the verified directory tree immediately before the native request. Run without `--auto-eject` for a verified-copy report that leaves the session mounted. The timeout and a busy volume leave the session available for inspection or manual unmount. This foreground profile checks observed copy state and requires external mount tools and filesystem writers to coordinate during the final check. [Watcher CLI tests](../../apps/dmgez-cli/tests/mount_cli.rs) · [Bounded D-V14 watch model](../../crates/platform/dmgez-mount/verification/README.md)

`dmgez mount App.dmg --watch-install /App.app --destination /Applications/App.app --auto-eject --detach` is proposed syntax. Monitor only explicit source/destination; repeated pairs support multi-app AND default, explicit ANY opt-in. Require `--auto-eject` plus a fresh per-session intent, read-only mount, validated source bundle and destination root. Record initial destination state/identity and source manifest/digests. A destination already matching at startup is not a completed new copy. Use notify/platform notifications as hints only; debounce bursts, reconcile on lost events, periodic bounded check within user-set timeout. State `WaitingForChange -> Candidate -> Quiescent -> Verifying -> Matched -> EjectRequested`. Candidate must exhibit post-start change relevant to this intent; no generic global monitoring. Verify full file set and required metadata/bytes (signed bundles optional native verification) against frozen source manifest after quiescence, compare destination identity and post-verification re-stat; if changed or ambiguous return to wait. Repeated events reset quiescence; existing matches, incomplete files, rename races, wrong app, permission issues, copy failure, cancellation, unexpected extra files under strict policy all block auto-eject. Even full verified match cannot prove Finder operation semantics or that no process will later write; rely on safe non-forced unmount and fail closed. Busy -> report/retry bounded with backoff or user choice; no force. Never eject merely on idle timer. User can stop monitoring without affecting other sessions. Timeout leaves mount attached and reports reason.

## Qualification

Test driver absent, invalid path, mount conflict, shutdown/crash, stale session, identity change, unmount busy, unauthorized other user's mount, FUSE read boundary and malicious source. On macOS actual Finder drag into disposable destination test copy success, slow copy, preexisting identical app, canceled copy, overwritten files, multiple bundles, lost watcher events, modification after verify, busy open file. On all platforms test virtual browse independent of drivers; mount backends individually qualify and advertise support only when installed. No mount/notify dependency in default builder.
