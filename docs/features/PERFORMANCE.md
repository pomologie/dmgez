# Streaming, concurrency, reproducibility and cache (D-PERF-01 through D-PERF-03)

The primary advantage is eliminating full-sized intermediate raw storage. Use immutable HFS+ plan reads; source payload is read in bounded slices, catalog/metadata memory is proportional to entry/run count, independently capped or optionally spooled. A source snapshot may require temporary storage when immutable input cannot otherwise be assured; report it. Do not claim all workloads use constant RAM. Set an initial default budget proposal: 512 MiB aggregate payload/cache working memory, 128 MiB metadata budget, 1 MiB preferred chunk size (profile-qualified), 1 million entry ceiling (configurable), 2 million run ceiling (configurable), worker count automatically selected from available_parallelism and memory. These are tunable proposals, not filesystem maxima or benchmark results. Include decoder workspace, input and output capacity, queue, metadata, and codec overhead in accounting; memory_limit is an owned working-set target, not an OS RSS hard cap. Reject a request if one chunk cannot fit. Track actual bytes owned, sample process RSS separately in benches. Allocate fallibly where possible; bound metadata count before parsing. Use explicit timeouts for remote/FFI requests.

## Compression scheduler

Serial code is correctness baseline; optional Rayon private pool is reused per operation, default-on, no global pool assumptions. Acquire byte credits before reading chunks. Use bounded window of contiguous chunk indices, each worker gets immutable input and a bounded output allocation, returns encoded bytes or raw fallback. A dedicated ordered consumer emits contiguous completed runs; consumer not queued behind workers on same saturated pool. Producer never holds a lock needed by consumer while waiting. First error propagates cancellation; drain and join all workers, release credits. Output order independent of finish order. Avoid unbounded `par_iter().collect()` across entire image. Reserve enough bytes for worst-case encoded overhead, zlib workspace and raw source; if codec cannot bound expansion, use capped sink and fallback or abort. Number of concurrent jobs <= configured threads and budget. Reader disk access sequential by default; parallel read only for sources reporting safe random access, to avoid thrashing HDDs. Known zero ranges avoid unnecessary read/compression, but must be semantically exact and included correctly in checksum domains. Hash order qualified as UDIF spec. One writer owns cursor and checksum state. Test out-of-order completions, first/middle/last job failure, memory limit lower than chunk, cancellation while queue full, thread panic to typed failure where practical, and identical serial/parallel bytes with same unsigned profile.

## Reproducible unsigned artifact

Fix traversal order to filesystem comparison rules; generated timestamps/IDs derived from explicit epoch and deterministic inputs; stable CNIDs, allocation, plist serialization and codec profile/version; no wall-clock metadata, random salt or temp path leakage into image. Preserve source bytes/metadata by default and document which metadata differs across hosts; cross-platform reproducibility requires same logical manifest and available metadata, not merely equivalent filenames. Explicit source timestamp normalization can affect signatures or semantics; do not rewrite signed bundle internals. If identity derivation is based on content hash, calculate in bounded prepass and verify unchanged sources; no hidden reread overhead. `SOURCE_DATE_EPOCH` only if explicitly enabled and recorded. Output digest in report. Do not promise reproducibility across compressor updates or sign/notarize stages. Compare images by semantic diff first; raw bytes only for same qualified profile. Release gate serial/parallel and independent process repeat; cross-platform repeat with identical canonical manifests. Benchmark reproducibility overhead separately.

## Incremental cache and optimization (optional)

Cache compressed blocks content-addressed by uncompressed bytes, codec identity/version/options, length, framing, and canonical run kind. Logical offsets are not sufficient cache keys. Verify digest and decoded length of cached payload before use; corrupted or untrusted cache miss and regenerate, never trust cache for signing. Keep cache root scoped, private permissions, atomic writes, LRU size budget, concurrency locks and no symlink escape. Disabled by default even when compiled. Don't persist decrypted bytes or signing secrets. Deterministic layout and stable chunk boundaries improve hit rate; metadata shifts can invalidate many blocks. Optimize by sampling bounded representative chunks and evaluating size/time under a specified budget; output explicit selected profile, never claim optimum, no experimental algorithm affecting validity. `analyze` separates measured current build timing from image-only facts (no historical timing derivable from finished DMG). Optional JSON/trace events.

For unsigned UDZO projects, compose the CLI with `compression-cache` on macOS or Linux. Create a private directory with mode `0700`, outside the project's copied sources and output location, and set its path and byte limit in the project. Relative paths resolve from the project file's directory.

```toml
[performance.cache]
directory = ".dmgez-cache"
max_bytes = "512MiB"
```

A cache hit decodes one complete zlib stream and compares every logical byte with the current chunk. Failed candidates are compressed afresh. The builder prints the hit, miss and rejection counts. Dry runs validate the directory without writing entries, and requested release builds encode the unsigned signing input afresh. Intact entries from the pinned encoder retain identical output bytes. A different valid zlib representation of the same logical bytes can change the physical output, so use the cache-free profile when physical reproducibility must hold independently of cache contents. ## Performance qualification

Benchmark 100 MiB, 1 GiB, 10 GiB, 100k tiny files, all-zero, mixed compressibility, large already-compressed payloads, Unicode tree, signed multi-app. Compare against dmgbuild and fstool only with equivalent content, format/codec/level, filesystem and preservation policy; report differences explicitly. Record hardware, storage, OS, compiler, features, codec version, source dataset digest, warm/cold caches, repeats (>=5 where practical), median and p95 if sample sufficient, throughput, output size, temp bytes, memory RSS/owned allocations, CPU time and stages. Include serial and 1/2/4/8 worker caps. Establish baseline before performance claims; candidate goal no full-sized raw intermediate, bounded owned working set and memory slope as payload size rises, near-linear time for streaming I/O, no deadlocks, relative regression alerts >10% wall time on controlled runner (investigate, not blindly fail variable hosted runner), size regression >1% with same profile (explain). Do not demand speed superiority before correctness. Signed output and network latency excluded from codec comparison. Large benchmarks scheduled/manual, small invariant benchmarks in CI.
