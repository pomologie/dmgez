# Configuration, content manifests and builder (D-BUILD-01 through D-BUILD-05)

The canonical external document is `dmg.toml`, `schema_version=1` (draft until release); the internal typed project is independent of TOML formatting. Use serde with deny-unknown-fields where possible; no arbitrary expressions, shell, Python, dynamic imports or network source by default. The JSON Schema under `schemas/` is a tooling mirror, not a substitute for semantic validation. TOML includes no secret values. Paths in TOML resolve relative to the config file; CLI paths relative to explicit working directory. Output and source may not alias, including symlinks/hard links. A base path explicitly selected by user is allowed; MCP adds an authorized root. Include/exclude patterns operate on normalized relative slash paths, include dotfiles by default, and never follow symlinks. No implicit `.gitignore`. Globs only on recursively copied directories, not arbitrary destination paths. Resolve variables only `${NAME}` from `[defines]` plus CLI `--define` (explicit allowlisted environment mapping if added). No environment interpolation by default. Unknown variables error. `--set` uses typed keys and validation, no eval; precedence built-in defaults < TOML < explicit defines/overrides, no secret leakage in reports. Preserve comments with toml_edit when the GUI saves; show diff and schema migration rather than discarding unknown user edits. For schema version unsupported, fail, never reinterpret.

## Schema semantics

- `[image]`: `name`, `output`, `format` (`udro`, `udzo`, `ulfo`, `ulmo`, `raw`, `udrw`, `udsb`, `sparseimage`, `asif`, `udbz`, `udco` are recognized draft identifiers; unsupported ones must fail), filesystem (`hfsplus` default, `hfsx`, future `apfs`), size (`auto` or aligned positive bytes/IEC string), shrink (choose minimum planned capacity if true; if explicit size, it acts as maximum allowed when shrinking; false honors explicit size, auto reserves documented free space), free_space (minimum padding), partition (`none` default; `gpt`, `apm`, `mbr` opt-in). Reject ambiguous capacity policy, invalid volume labels or format/filesystem combinations. First releases implement HFS+ and UDRO/UDZO; raw CLI export/import is deferred to conversion in 0.7 (standalone HFS+ raw construction already exists in its initial milestone); `dmgbuild` compatibility profile maps semantics instead of copying macOS resize side effects. Auto size includes all catalog/attr/fork/generated files and alignment. No arbitrary file count limit in schema, but explicit resource limits and format maxima.
- `[[contents]]`: `type=copy` default with source and destination; type `directory` creates an empty directory without source; type `symlink` requires destination and target bytes/path, not source. `recursive` default true for directories; false is valid only when no descendants copied. Multiple apps, packages, documents, nested paths, hidden content, explicit symlinks and directory entries; .app is simply a directory tree, not a separate storage abstraction. Destination defaults to `/<basename>` for copy only; path is absolute within image, no `.`/`..`, trailing separators, NUL, host drive letters or alternate stream semantics. Create missing parents deterministically; conflict with explicitly declared dirs merged only with compatible metadata, duplicate entries error unless explicit future edit operation replaces. Validate HFS+ normalized comparison collisions before writing; also reserve generated root `.DS_Store`, hidden assets, `.VolumeIcon.icns`, HFS private metadata, etc. No silent overwrites. `hidden` modifies Finder flag not inclusion; `hide_extension` updates recognized Finder metadata. Dotfile naming and hidden flag independent. `position=[x,y]` is a folder-relative icon center; parent layout determines coordinates. `custom_icon` optional and prohibited from mutating signed bundle internals. `include` and `exclude` operate only on source tree; exclusion wins; preserve required ancestor directories. Explicit source symlinks are copied as links; no traversal or target access. Hard link grouping from actual source IDs, not equal bytes; no dedup that alters semantics. Use source entry type-aware host adapters for junctions/reparse points and reject unknown special types.
- `[metadata]`: defaults preserve modes, uid/gid if available, timestamps, xattrs, FinderInfo, resource forks, hard links; policy `strict` default for known required fidelity, `report` explicitly permits representational losses and reports them. Optional `sidecar` points to explicit versioned manifest/AppleDouble handling, never guess arbitrary `._` files are metadata. For known Mac bundles, missing critical executable modes/symlink structure may be undetectable if already lost; require an explicit metadata provenance profile or user declaration when host cannot prove preservation. Use synthetic permissions only for generated items or explicit overrides. Never silently strip quarantine or security attributes, do not promise to restore unknown ACLs. Capture metadata through opened file identities and compare pre/post reads; stable metadata check is not a cryptographic snapshot under concurrent hostile writes; optional staging snapshot gives stronger guarantee.
- `[compression]`: level integer 0..9 for qualified zlib backend, block_size IEC or integer (aligned to sector and capped by qualified codec maximum), raw fallback deterministic. Codec selected by image.format; level/size options for disabled/incompatible codecs fail. `[performance]`: parallel auto/true/false, threads=0 auto, memory_limit, max_entries, max_metadata_bytes, max_runs. Resource budgets in bytes and counts. `[build]`: reproducible=false, source_date_epoch optional; verify_output=false (explicit full verification requires `verify` feature); overwrite=false; fail_on_metadata_loss=true for strict profile; never verify signing or Gatekeeper by default. Staging rules per C7. `[finder]`, `[volume_icon]`, `[[finder.folders]]`, `[signing]`, `[notarization]`, `[release]`, `[license]` owned by their feature specifications. `[defines]` string substitutions. Paths are strings, not URLs unless explicit remote profile; optional source types introduced with new schema version.

## Build stages and manifest

`plan` does semantic validation and feature preflight without writing final output or making network requests. Validate inputs before expensive work, then walk once (iterative, capped depth) collecting identity/stat/link metadata and source stream references. Keep original user path, canonical image path, parent and stable entry ID, not arbitrary host path traversal later. Represent content source as `FileRef`, `GeneratedBytes`, `ResourceFork`, or `ZeroRange`. Use verified sizes and open-time identity checks, bounded reads, link bytes, raw metadata. Manifest is deterministic sorted by filesystem comparison key and stable tie rules; duplicate canonical names are errors. Distinguish entry count, regular payload bytes, allocated volume bytes, generated metadata and planned overhead. Hidden files are counted even when invisible. Build planner requests filesystem IDs, generates Finder assets, then seals plan according to C3. Source metadata is captured before overrides; apply only explicit policy and show report of changes. For reproducibility normalize only selected generated/volume metadata and explicit source timestamp/ownership policy; do not mutate source bundles. See PERFORMANCE.md.

`dry-run` emits resolved manifest, predicted virtual size, requested format, capabilities, source losses, collisions and potential signing or layout issues. Compressed output size is unknown, not a fabricated exact number. Dry-run must not sign, create final image, mount, notarize, or extract. No implicit long I/O beyond required metadata scans; optional prehash user requested. Actual execute uses sealed plan, bounded compression, atomic publication. For a signed app test compare bytes and metadata of mounted app vs original; codesign validates only signing semantics, not all file attributes. Use `--release` separate opt-in for signing pipeline, and reject `--release` with uncompiled features before work. Release signs staged copies, never source paths by default. Cancellation checked between files, reads and compression runs; cleanup only generated staging files. On errors return typed stage diagnostic. `build` may generate report JSON to caller path and print human progress to stderr. No progress on binary stdout. Validate full output only if requested and enabled; writer always enforces own structural invariants.

The current macOS and Linux `build` command shares the HFS+ preparation, sealing, and publication service with the compatibility runner. Its CLI tests exercise the dry-run and publication paths under D-BUILD-01 and D-BUILD-05. The local composition tool resolves exact versioned HFS+ packages from explicitly supplied sources and compiles a standalone binary. The ordinary workspace can link the same service when the HFS+ packages are available from the release registry. See the [local build instructions](../../README.md#build-from-a-toml-project) and [CLI tests](../../apps/dmgez-cli/tests/project_build_cli.rs).

### Read the build report in CI

Use `dmgez build dmg.toml --dry-run --json` to get the admitted plan or `dmgez build dmg.toml --json` for the unsigned publication report. Both emit one JSON document on stdout with `schema_version: 1`, `operation: "build"`, and a `mode` of `"dry_run"` or `"published"`. The `output` field is the resolved host path in display form. Byte counts use decimal strings. `physical_bytes` is `null` when the plan cannot predict the final byte count and always has a value after publication. Both modes report metadata-loss counts and release policy. The dry run also reports the filesystem, Finder layout, and publication policy. In a publication report, `verified` records whether the requested staged image check completed.

Build progress and diagnostics go to stderr. Failed unsigned builds return a nonzero exit code with no success report on stdout. A dry run with `--release` reports the planned release policy. Executed releases emit the [release report](RELEASE.md). The composed CLI regression exercises planning, publication, and refusal to replace an occupied destination for D-BUILD-01 and D-BUILD-05 and covers the unsigned report interface required by D-CI-03. [JSON build regression](../../apps/dmgez-cli/tests/project_build/json.rs)

With `finder-write` enabled, `hidden` and `hide_extension` apply to file, directory and symlink catalog records after host metadata capture. Set either option to `false` to clear its bit. Omit an option to preserve the captured value. Hard-link aliases share FinderInfo, so conflicting explicit values are rejected. The builder checks affected paths and sources for signing-sensitive content before applying display overrides. [Apple code-signing restrictions](https://developer.apple.com/library/archive/qa/qa1940/_index.html)

### Write an APM or GPT disk layout

Compose the HFS+ CLI with `--features partition-write`, then set `partition = "apm"` or `partition = "gpt"` under `[image]` in `dmg.toml`. Both profiles place one sealed HFS+ or HFSX volume within a single-table UDRO or UDZO image. Add `lzfse` to the composition features for ULFO or `lzma` for ULMO. The default remains `partition = "none"`.

`image.size` describes the entire logical disk. The filesystem planner subtracts the map reservations from that size and applies `free_space` within the volume. The dry run reports the selected map and whole disk size. APM reserves 64 sectors before the volume. GPT reserves 40 sectors at each end and derives reproducible identifiers from the sealed volume bytes. Map generation uses the qualified APM and GPT libraries. [Partition build tests](../../apps/dmgez-cli/tests/project_build/partitions.rs)

On arm64 macOS 14.7.2, Apple’s `hdiutil verify -nocache` and `hdiutil pmap` accepted freshly built APM and GPT images in UDRO, UDZO, ULFO and ULMO. The test checks that compressed images contain a run in the selected codec. Apple’s UDRW export matched dmgez’s whole logical disk export. The volume bytes also matched a separate partitionless UDRW build from the same project. [Native oracle in the project test](../../apps/dmgez-cli/tests/project_build/partitions.rs)

### Import one AppleDouble sidecar

On macOS and Linux, set `sidecar = "sources/._Manual.pdf"` under `[metadata]` to supplement the single included regular source `sources/Manual.pdf`. The association follows the host source name, so the file can have a different image name. When copying a directory, exclude the named sidecar from image content. The build rejects ambiguous associations, hard-linked targets, and custom icons on the same file.

The admitted AppleDouble version 2 profile carries a resource fork, Finder information, and the bounded macOS `ATTR` layout with ordinary attribute names and values. The build checks the admitted file identity when reading both sources, merges equal values once, and rejects conflicting native metadata under either metadata policy. The normal per-field preservation settings still apply. Versioned multi-file manifests, AppleDouble ACL and compressed-file records, and Windows sidecar import remain outside the current profile. [RFC 1740](https://www.rfc-editor.org/rfc/rfc1740) · [Apple copyfile documentation](https://github.com/apple-oss-distributions/copyfile/blob/main/copyfile.3)

D-BUILD-03-T03 was exercised with AppleDouble produced by `ditto` on arm64 macOS 14.7.2 and HFS+ packages from `fb11b35`. Native readback of a disposable image matched both forks, Finder information and the imported extended attribute. A different native resource fork caused the build to fail before publication. [Builder sidecar tests](../../crates/build/dmgez-builder/src/metadata/sidecar/tests.rs)

## Cross-platform safety and acceptance

Use native POSIX on macOS/Linux; Windows host needs verified manifest and supported Windows reparse adapter. AppleDouble import understands documented records, limits lengths and conflicts (RFC source S08); AppleDouble does not recreate data not provided. Test raw directory staging and metadata manifest ingestion with synthetic signed/ad hoc bundles. No reading arbitrary absolute symlink destinations during build. Test input replacement, case-fold and decomposed name collisions, root-reserved names, nested parent conflict, multiple app bundles, multi-gig file, hard links, xattrs/resource fork/ACL representation and unsupported metadata warnings. Build on each OS and attach same profile on macOS. Ensure no mandatory native commands in default binary; isolated CI runner with PATH stripped of optional tools. Test low-memory failures before unsafe allocation, progress and cancel cleanup, no-clobber and replace races, old artifact intact on failure, stdout-only data mode. P0/P1 acceptance in test catalog.
