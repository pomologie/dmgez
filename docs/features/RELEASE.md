# Signing, notarization, release validation and lint (D-REL-01 through D-REL-04)

Use shared release stages over existing DMG and application artifacts. Optional `apple-codesign` Rust backend, native macOS backend orchestrating codesign, notarytool, stapler, and native assessment tools. Only sign with user-authorized Developer ID identities and Apple service credentials; no private key embedded in source/config, no Gatekeeper bypass. Apple guidance S09-S10. Distinguish `native` on macOS, `rust` cross-platform, `auto` explicit capability resolution per operation (prefer usable native on macOS; otherwise Rust if compatible). Select backend during plan; log chosen backend and reasons, do not silently change after side effects or failed authorization. Backend-specific support for DMG signing/stapling and bundle signing must be verified against actual pinned library API; do not promise native parity. `apple-codesign` may depend transitively on `apple-dmg`, allowed for signing only. DMG builder itself remains independent. Native tools use trusted paths and argument arrays, fixed environment/timeout; never shell interpolation.

## Pipeline

1. Plan inputs, validate credentials/capabilities without exposing secrets. Stage source apps if sign requested; default `[signing].apps="verify"` checks existing signatures and does not re-sign. `preserve` packages without claiming validity; `sign` explicit and stage only. Inspect nested Mach-O, frameworks, plugins, helpers, dylibs, bundles; per-path signing policy/entitlements, sign inside-out; no blind `codesign --deep` for signing. Preserve symlinks and resources. Validate Developer ID Application identity, secure timestamps, hardened runtime for eligible executables, and entitlement policy; signing alone does not satisfy Apple requirements.
2. Build unsigned DMG from staged/preserved app, verify structure and requested manifest. Signing DMG afterward may alter trailer and signature regions; use correct qualified backend, not homegrown cryptographic signing. Capture unsigned digest for reproducibility; signed digest distinct. Never modify signed bundle just to change icons. Edits to signed images invalidate signature/ticket unless verified otherwise; report and require re-signing, never retain stale trust badge.
3. Submit signed artifact to Apple notarization service using chosen backend. Requires network, eligible account and credentials, exact submitted artifact digest. Persist a private nonsecret submission record with submission ID, digest, backend, timestamp/status; resume polls by ID, never blindly resubmit ambiguous upload. `--wait` or explicit status subcommand; no background service needed. Bounded backoff/retry and cancellation; pending/accepted/rejected/unknown distinct. Save redacted diagnostics/notary log. Cancellation of local polling does not cancel Apple's remote process; communicate this. Apple acceptance not equivalent to running correctly.
4. Staple accepted ticket to exact staged artifact; validate ticket via supported backend, native `stapler validate` where available. Reopen final image and verify structural integrity and unchanged disk semantics. On native macOS test trusted signed app, actual mount/copy, signature validity and current Gatekeeper assessment appropriate to OS version (qualify `spctl`/`syspolicy_check` etc. by target). Rust signature inspection/cryptographic checks are not native policy evaluation. A ticket's presence is not proof of acceptance or validity. No network by default outside explicit release actions.
5. Produce `ReleaseReport`: per-stage required/optional/skipped, passed/failed/pending/unavailable, backend/version, artifact digest, cert fingerprint/nonsecret selector, notary ID/status, structural and native policy checks. `require_notarization` and `require_native_assessment` must fail release if required evidence unavailable, not mark skipped success. Stage commit only after all required gates pass. User may retain failed artifact/log explicitly outside final release path; do not publish invalid output.

## CLI/config

`sign inspect`, `sign app`, `sign dmg`, `sign verify`, `notarize [--wait]`, `notarize status ID`, `staple`, `lint --profile macos-release`, `test --profile installer`, `build --release`. All explicit signing/notary actions behind appropriate features; default `build` ignores no requested behavior: if config sets enabled but command lacks `--release`, report that configured stages were not executed; do not claim release-ready. `[signing] enabled, backend, apps, dmg, identity, credential_ref` and optional `[[signing.rules]]` match path and entitlements file; `[notarization] enabled, backend, wait, staple, credential_ref`; `[release] verify, require_notarization, require_native_assessment`. Secret references are opaque names resolved from Keychain, restricted environment or secure provider; no raw p12 content/password/private key allowed in TOML or CLI history. Use protected local file mode or stdin/secret provider where possible; avoid argv secrets and redact errors. Do not expose secrets to MCP, GUI logs, crash reports or test fixtures. Zeroize where possible. CI credentialed tests restricted to trusted branch and manually approved runner.

## Semantic diff and lint policies

Diff supports `contents` (BLAKE3 + optional exact stream compare), metadata, links, resource forks/xattrs, Finder semantic settings, filesystem allocation/raw records, UDIF physical maps/codec/byte differences, signature metadata; physical and logical differences separate. Compare normalized paths with each filesystem's rules; case/normalization ambiguities diagnostic. Compare volume IDs/profile explicitly. No implicit timestamp suppression; optional policy ignores listed fields and reports exclusions. Detect unchanged/added/removed/changed/renamed candidate (rename inference clearly labeled). Budgeted traversal, hash cache scoped to immutable identity, parallel only as allowed. Return machine diff including unknown/not compared. CI exit 0 equal under policy, 1 differences, 2 error/unsupported. Lint profiles `installer`, `macos-release`, `layout`, `strict-metadata` use typed rule IDs severity and evidence, suppressions explicit with reason. Rules: missing expected Applications link, incorrect target, overlapping icons/labels, background missing, size/scale mismatch, unsafe path, duplicate canonical names, suspicious external symlink (normal Applications link allowed), unexpected visible private assets, missing executable mode/Info.plist executable, missing signature/hardened runtime/ticket where requested. Lint never auto-fixes signed content; suggested changes separate. Release checks run native tools only when explicitly requested.

### Compare filesystem contents

For a CLI composed with `diff` and the selected reader, `diff LEFT RIGHT --mode semantic --filesystem hfsplus|apfs` compares two opened volume trees. Each side can select a raw image, partition slot, and, for APFS, a volume UUID or object ID and exact retained XID. Diagnosed APFS checkpoint recovery requires an explicit retained XID on the affected side. Reports identify both selected disk windows and include HFS+ or HFSX signatures or APFS volume and checkpoint identities. The outcome describes the tree comparison policy.

The baseline policy matches exact stored Unicode spellings and reports paths as arrays of components. It compares object kind, POSIX mode and ownership, visible hard-link groups and counts, symlink targets, and regular-file data and resource forks. Forks compare by exact bytes and available stream presence. HFS+ exposes an empty stored resource descriptor as a zero-length stream. APFS reports absence when the resource attribute is missing. The report lists its policy, limits, and exclusions, including timestamps, Finder settings, allocation records, and signatures. Native normalization matching, content hashing, and rename inference remain separate work.

Add `--xattrs` to compare stored attribute names and exact values on common paths. Complete listings establish whether a name was added or removed, including a present empty value. Values for matching names share the fork payload budget. Reports contain names and change kinds. An uncheckable listing, invalid name, unreadable matching value, or exhausted budget stops the comparison. The policy identifies its name limits and excluded records for resource forks, Finder info, compression, symbolic links, and access-control lists. Quarantine records compare as stored bytes. Trust assessment remains separate.

The comparison reads under bounded catalog and payload budgets. `--max-bytes` controls the compared logical payload bytes per side. Exit codes are 0 for equality under the reported policy, 1 for differences, and 2 for an unsupported operation, read error, or exhausted budget. Reports sort changes by stored path components. ### Lint project layout

The implemented `layout` profile evaluates one declared project folder at a time. The CLI and desktop editor use the same declared entries, implied directories, and preview geometry. It reports clipped or overlapping configured icon rectangles, icons outside the viewport, positioned hidden entries, automatic arrangement, and tight grid spacing. `--folder` selects a virtual folder and `--suppress RULE=REASON` retains the diagnostic with its suppression reason. `--json` includes the selected folder, viewport, stable rule IDs, and evidence. Linked source trees, mounted Finder behavior, labels, installer policy, and release trust have separate qualification requirements.

The [layout service fixtures](../../crates/services/dmgez-lint/tests/layout.rs) and [CLI integration tests](../../apps/dmgez-cli/tests/lint_cli.rs) exercise the icon geometry and suppression portion of `D-REL-04-T01`. The full acceptance case also requires installer rules and native release checks.

## Native qualification

Use synthetic ad hoc bundles for noncredentialed CI, and properly signed Developer ID fixture owned by project for protected end-to-end notarization. Compare app signature and exact bytes before/after build/extract, DMG signatures across backends, native attach/staple validation, failed/expired credentials, rejection, interrupted/resumed submissions, changed artifact after acceptance, native tool missing, partial report and no publication. Document backend versions/OS. Unit test mock service without claiming real Apple acceptance. No network, signing or notarization dependencies in default builder. No redistribution of Apple binaries, signing keys or actual private notary logs.
