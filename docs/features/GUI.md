# Desktop studio, actual-image preview and virtual browsing (D-GUI-01 through D-GUI-03)

Separate `apps/dmgez` (package/binary dmgez-gui) built with egui/eframe, custom restrained native-style presentation rather than stock demo UI. Shared project/manifest/reader services; no duplicate implementation. No Electron, no OS mount needed for normal preview. Use dockable or resizable panels; command palette and keyboard shortcuts discoverable. Screen reader labeling, keyboard navigation/focus, scalable fonts/zoom, high contrast and status indicators not color-only; egui accessibility limitations documented and tested with platform tools. UI thread never blocks on disk reads, decode, builds or network; bounded background work, cancel tokens and progress/events. Handle large trees/blocks with virtualization, pagination and indexed queries. Native file dialogs, recent files (local opt-out), unsaved changes prompts. App open can read local `.dmg` or project file; never run image content or follow remote URLs automatically. Cache preview textures within pixel/byte budget; malformed images safe errors. Linux/Windows fallback icons independently authored or licensed; on macOS optional system API obtains native file kind icons under permitted terms.

## Builder workspace

Three panes: project/content tree, center interactive design canvas, property inspector. Canvas is virtual Finder window with actual background in logical points, scale-independent guides, viewport, icons and labels. Drag arbitrary files/directories from host, multi-select, rename destination, create directories, symlinks and Applications shortcut, visibility and extension toggle. Drag position in canvas (folder-local points), snap-to-grid optional, align/distribute, keyboard nudge, multi-selection bounding boxes, undo/redo grouped gestures, zoom/pan, precise numeric coordinates. Inspector tabs image/compression/content, window, icon/list view, volume icon, advanced and output. Show folder-scoped layouts; nested folder navigation. Multi-res background and ICNS asset chooser, preview different window sizes/scales and light/dark surroundings, warnings for clipping, overlap, missing backgrounds/aliases/targets. Templates are ordinary versioned TOML + licensed assets (single app, multiple apps, docs, file-distribution). Fit window to background optional explicit command. No arbitrary per-icon display size: icon view size applies folder; individual custom image reps vary with scale. `toml_edit` preserves user's comments and formatting; editor keeps semantic model and original syntax tree, applies typed patches; conflicts/unknowns require user resolution. Save validates and records revision; unsaved preview can render model, build from snapshot, no implicit overwrite. Load existing image as read-only then explicit Edit creates project/overlay, no destructive edits. GUI can invoke dry-run, build, cancel, inspect result, compare, preview, release checks if compiled. Task progress stage, actual bytes/files, no unresponsive spinner.

Select several icons in the same folder with Shift-click or Ctrl/Cmd-click. The **Arrange** menu aligns two or more icons and distributes three or more between their existing endpoints. With focus on a selected icon or its row, use the arrow keys to move the selection by one Finder point or Shift-arrow to move it by ten. Each command is one undo step. All selected items must be visible on the canvas and declared in the project. Icons positioned by a Finder folder table use that table as their source. [Arrangement and undo tests](../../apps/dmgez/src/project/tests.rs)

With the `preview` feature, `dmgez preview --project dmg.toml --output design.png` renders a declared icon view with the shared folder geometry and CPU text layout. Use `--folder` to select another folder. [Design PNG profile](../../crates/presentation/dmgez-preview/README.md#render-a-project-design-png)

The composed desktop `project-build` feature runs the shared HFS+ build workflow against the current editor snapshot. The plan action reports geometry without publishing. The build action requires a new output path and reports progress and metadata omissions on the document worker. A successful UDIF build can open in the image inspector. This covers the unsigned desktop build path of D-GUI-01. [Desktop build commands](../../apps/dmgez/README.md#build-a-project-from-the-desktop)

Explicit project save on macOS and Linux uses the opened file's identity and exact saved text to guard atomic replacement. Tests exercise repeated saves, stale files, and saving a copy. [Project save tests](../../apps/dmgez/src/app/project_save/tests.rs)

## Virtual image explorer

Open an actual DMG via read-only VFS. Default workspace recreates Finder-style display using decoded `.DS_Store`, backgrounds, actual bundled ICNS/Info.plist metadata and volume state. Unlike a screenshot, interactive icon/list view, directory navigation, back/forward, search, breadcrumbs, selection, keyboard open, info panel, hidden toggle and fork/attr inspection. Do not recreate Finder implementation or proprietary assets; geometry/behavior close within documented tolerances, native Finder is final oracle. `PreviewMode::Design` editable positions; `Actual` read-only layout from image; `Native` optional macOS attach through managed backend, explicit user request. `Actual` does not mutate `.DS_Store`. Fallback generic layout if absent/corrupt metadata with clear warning. Symlink `/Applications` is a virtual shortcut action, never a host path inside the VFS. Double-click `.app` opens metadata/bundle inspection or asks user for explicit extract/install, never executes. External document opening requires explicit extraction to managed temp, no executing content; mark untrusted/quarantined as appropriate and cleanup. Preview text/images capped; arbitrary PDF/media handlers optional sandboxed or explicit external opening; no automatic active content. Read-only graphical preview PNG can be generated headlessly (`dmgez preview actual.dmg --output preview.png`) using shared geometry and render pipeline; generated project preview distinct with source label. No GPU required for headless rendering (qualify CPU renderer and font licenses).

The composed HFS+ desktop app provides a **Files** workspace with paged catalog listings, folder navigation, and entry details on the opened image handle. It checks the selected data window through the sibling reader. This covers the folder-browsing portion of D-GUI-02. [Desktop composition and tests](../../apps/dmgez/README.md#browse-hfs-and-hfsx-files)

Entry details report the logical data fork length, stored resource fork length, and bounded extended attribute names through the shared inspector. A failed fork query retains its diagnostic alongside other storage observations. Native fixture tests cover hard links, compressed files and empty attribute inventories. [Storage detail tests](../../apps/dmgez/src/image/browse/tests/storage.rs)

The optional `actual-preview` feature reads the observed Finder icon layout, catalog entries and qualified in-volume background artwork from the chosen HFS+ or HFSX folder. The CLI exports a PNG with an observation report. The desktop displays the same renderer’s output with visible fallback states. [Actual-image preview profile](../../crates/presentation/dmgez-preview/README.md#render-an-actual-disk-image)

The desktop accepts pointer or keyboard activation on the rendered icon bounds and uses exact catalog names for folder navigation and item details. The hidden item control preserves the choice across folders. Search and folder history operate through the held image and retain exact catalog selections. [Preview activation tests](../../apps/dmgez/src/inspector/browse/preview/tests.rs)

## Inspector workspace

The run table accepts a decimal or hexadecimal logical byte offset and selects the corresponding run on its page. The shared runtime uses the admitted UDIF index and revalidates the held source. [Run lookup tests](../../crates/runtime/dmgez-runtime/src/image/tests.rs)

The inspector exports current inspection and completed verification reports as versioned JSON. A selected run with an available decoder can be exported as logical bytes within the 64 MiB limit. All exports stage to a new path and revalidate the held source before publication. [Export tests](../../apps/dmgez/src/app/image_exports/tests.rs)

Split image tree (container -> partitions -> volumes -> folders/internal structures) and typed property/detail panels. Search/sort tables for UDIF runs, offsets, compression, extents, checksums, node counts, raw record hex view with pagination; select file to highlight covering UDIF blocks. Separate actual status vs requested verification. Export JSON, report and selected safe raw bytes. Diff view side-by-side tree and changes (file bytes, metadata, presentation, format); click to drill. Integrate layout lint preview overlay. No data recovery controls. Large image still usable via lazy reads/cancellation and capped previews. Build analyzer only displays historical timing if report provided, no inferred times.

## Actual OS drag-out and mount

Internal drag of bundle onto virtual Applications shortcut invokes explicit install service, including collision confirmation and destination verification; external drag to Finder may use `NSFilePromiseProvider` (directory UTI, one promise per top-level bundle) via native adapter; qualify directory promise behavior and metadata on actual macOS. Completion callback after verified extraction; preview may close only on successful operation when configured. Windows virtual-file descriptors/content streams and Linux desktop file transfer mechanisms have distinct directory support; staging fallback explicit and cleanup; no promise all file managers behave alike. Never silently copy into OS Applications on drop outside expected user destination. Actual host mount optional, not required for preview; see MOUNT_INSTALL.md. GUI should still fully browse images if no mount backend installed. Headless preview has no GUI dependency.

## Test strategy

Unit-test geometry/coordinates, command reducer, undo/redo, TOML roundtrip and schema migration. Simulated pointer/keyboard flows and accessibility focus tests; screenshot baselines use synthetic icons/fonts and tolerances, real Finder comparison on supported macOS. Large 100k-entry tree virtualization, 20 GiB sparse image inspection, cancel preview, corrupted assets, permission-denied export. Cross-platform UI smoke test on all 3 OSes. Native drag/drop tests use real Finder and destination on disposable directories, app bundles with symlinks/resources; no production application overwrite. Test preview from actual image (not its source config) and compare decoded background/positions to independent metadata oracle. Actual Finder screenshot not required for non-macOS build.
