# Finder presentation stores

`write_store` produces a deterministic `.DS_Store` for a folder in a newly built image. It takes the folder's settings and the final names and positions of its direct children. The standard records capture window bounds and chrome, icon-view preferences, default view, and icon positions. Window origins follow dmgbuild's screen coordinates with y increasing upwards. Icon positions are unsigned whole points with y increasing downwards. The color profile accepts `#RGB` and `#RRGGBB`.

The writer accepts printable ASCII item names. It supports icon view and list view as the default. Column view, cover flow, gallery view, image aliases, template backgrounds, and editing existing stores require additional qualification. The caller resolves folder inheritance and reserves the generated store before planning catalog IDs.

## List view

List layouts write both the keyed `lsvp` and ordered `lsvC` records. The configured column order determines which columns are visible. Width and direction overrides apply to hidden columns as well. Widths must be positive whole points within the signed 32-bit range. Auto inclusion writes settings for the default view and any explicitly configured secondary view. Explicitly disabling required settings returns an error.

The list writer follows the scalar and column shapes captured from macOS 14.7.2. It also serializes the two fixed scroll coordinates documented by dmgbuild. The fixture checks native widths, visibility and directions for all ten configured column types. The independent Python oracle checks both emitted plist representations. [Native fixture provenance](tests/fixtures/README.md) · [dmgbuild 2.0 settings](https://dmgbuild.readthedocs.io/en/stable/settings/)

Finder on macOS 14.7.2 opened a disposable read-only image carrying the generated store directly in list view. It showed Name, Date Added and Size in that order and listed the 6-byte sample before the 52-byte sample under ascending Size sort. The mounted store matched the generated bytes. Default and configured icon-only stores matched their pre-change bytes.

## Evidence

The fixture checks the icon layout-record portion of D-FINDER-01-T01. It covers deterministic encoding, binary record tags, window geometry, separate preview and item-info settings, exact icon centers, short hexadecimal color, validation failures, and the page boundary. Finder qualification of the full icon-layout acceptance scenario remains open.

The window and icon record choices follow dmgbuild 2.0. [Settings](https://dmgbuild.readthedocs.io/en/stable/settings/) · [Record emission](https://github.com/dmgbuild/dmgbuild/blob/v2.0.0/src/dmgbuild/core.py)

The pinned writer bundles the reader and alias codec. The package exposes no separate writer feature. [ds_parser 0.4.0](https://docs.rs/ds_parser/0.4.0/ds_parser/)

The writer is limited to one 4096-byte B-tree leaf. In a scratch test, `ds_parser` 0.4.0 wrote 200 synthetic icon locations and read back 200 without warnings. The independent reader found 202 records for those same 200 keys, including two duplicated separator records. The adapter measures every record before writing and rejects layouts that exceed one leaf. [ds_store 1.3.4](https://ds-store.readthedocs.io/en/latest/)

## Read-only inspection

`inspection::inspect` reports `bwsp`, `icvp`, `icvl`, `Iloc` and `vSrn` from single-leaf stores. The caller sets limits on input bytes, record counts, filenames and flat binary plist dictionaries. Unknown records retain their name and four-byte tags when their payload length is known. Unreported plist fields retain key names only. Alias resolution, free-list verification and multi-leaf inspection remain outside this profile.

The D-READ-02 layout checks use an independent Python-written synthetic store and an unchanged, Finder-authored fixture with three icon locations. The native fixture uses a 128-byte physical leaf allocation. The Python fixture uses an 8192-byte allocation for a 4096-byte logical leaf. Both allocations produce bounded record reads.
