# dmgez-inspector

`inspect` summarizes an admitted UDIF container without reading its payload. The optional run window returns bounded logical and physical ranges, original unknown run codes, and decoder availability. Block-map counts describe UDIF tables.

`inspect_disk` adds a bounded logical disk probe through `dmgez-vfs`. The optional `disk` object reports admitted APM, GPT or MBR entries, recognized partitionless HFS geometry, an unknown layout, or an unresolved layout with a redacted diagnostic. Partition ranges use decoded logical byte offsets. An unresolved layout retains the container summary and run page, including when a decoder is unavailable or the source cannot be read. All inspection coverage remains `not_checked`.

`verify` accepts an immutable UDIF source and reports the requested scope. Quick mode admits the metadata and ranges. Container mode decodes the stored runs and checks every declared checksum domain. Missing declarations remain `not_present`. Full mode reports partial coverage when the container passes and filesystem checks are unavailable. Security coverage stays `not_checked` in this profile.

`verify_filesystem` accepts an engine checker and runs it only after successful container verification and selection of one admitted filesystem data window. The checker receives window-relative reads under separate request and decoded-byte budgets. The UDIF reader also enforces its covering-run decode limits. The first failed read remains authoritative, and the inspector rechecks source identity before accepting evidence. Reports carry the selected window and optional engine-native volume ID. Reachable and structural checks remain partial, as do checks confined to one native volume or one of several data windows. A complete check of the only data window can satisfy whole-image filesystem coverage. Signature and trust checks remain independent.

`verify_filesystem_with_probe` allows an engine to recognize a bounded partitionless extent on an otherwise unknown disk and select a partition by its one-based slot. The probe and checker share the same source budget. `verify_raw_filesystem` uses this admission path on a raw disk and reports UDIF payload coverage as `not_present`. Checkpoint evidence can include the selected UUID, object ID, XID, logical payload bytes read, and a summary of rejected checkpoint descriptors.

Reports implement `Serialize` and include `schema_version`, `operation`, capabilities and per-layer coverage. Byte lengths and offsets serialize as decimal strings, and segment IDs serialize as fixed-width hexadecimal. Diagnostics record the first failure with a C6 category and numeric detail where the reader provides it. The local causal error is accessible through `VerificationReport::cause()` and stays out of the serialized payload. On an interrupted container scan the lower-level reader returns only the first error, so the per-domain fields retain declaration statuses.

The tests exercise the disk portion of D-READ-01-T01 and the container portions of D-READ-03-T01 and D-READ-04-T01/T02. They use [native Apple map fixtures](../../foundation/dmgez-vfs/tests/fixtures/native-maps.json), an instrumented metadata-only source, and synthetic map, source, checksum and run-code failures. Synthetic MBR cases exercise filesystem scope, bounded reads, source identity, and partial results for D-READ-04 and D-V09. Engine integration and full acceptance cases require separate evidence.

The `remote` library feature accepts an explicitly supplied `RangeTransport` for one resource. `RemoteSource` admits the image with a one-byte GET and requires exact partial responses, a stable strong ETag and identity encoding. Conditional reads share a request count, byte budget and deadline. The transport enforces origin authorization, TLS, deadline and HTTP framing.

Enable `remote-http` for the concrete `remote::http::HttpTransport`. It accepts a user-selected HTTP or HTTPS endpoint and requires an explicit exact `Content-Length` for partial responses. It rejects redirects, environmental proxies and content decoding, and applies verified TLS for HTTPS. The remote inspection CLI uses this transport and revalidates the admitted revision before returning metadata. [CLI profile](../../../docs/features/ADVANCED.md#remote-reader)

The in-process transport tests exercise the range semantics of D-OPS-03-T01/T02, including body transfer counts for inspection of a native UDZO fixture.
